# Security policy

## Supported versions

Security fixes target the latest version on the default `main` branch. Users of older releases should update to the latest revision before validating a fix.

## Reporting a vulnerability

Use [GitHub's private vulnerability reporting form](https://github.com/unclejobs-ai/second-claude-code/security/advisories/new) to contact the maintainer. Do not post exploit details, credentials, private prompts, or user state in a public issue.

Include the affected commit/version, host (Claude Code, Codex, or Grok), a minimal reproduction using synthetic data, and the observed impact. The maintainer will review the report and coordinate a fix and disclosure; no response-time guarantee is made.

## Runtime trust boundaries

This plugin runs local hooks and a bundled MCP server with the permissions of its host process. Install only in a trusted environment. The optional Playwright and MMBridge servers are separate integrations and are disabled by default in the Codex configuration. Network access and tool execution remain subject to the host's approval policies.

State may contain user content. Keep runtime state directories and local environment files private; never include them in a vulnerability reproduction. The MCP bundle is generated by maintainers, and installation does not require compiling or fetching its runtime dependencies.

## Automated checks

The Plugin Security Scan workflow pins the same HOL scanner revision used by the Awesome AI Plugins catalog. It uses read-only repository permissions, does not enable online probing or repository-owned scanner policy overrides, and requires a score of at least 80 with no critical/high findings. CI also rebuilds the bundled MCP runtime and runs the test suite.

A passing scan is a review baseline, not a guarantee that software is risk-free.
