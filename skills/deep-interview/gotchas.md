# Deep Interview Gotchas

## Skipping Round 0 breaks sibling coverage

Do not jump directly into a detailed component. Round 0 locks the top-level component list so a detailed UI request cannot hide ingestion, export, documentation, or runtime siblings.

## Asking codebase facts wastes the interview

For brownfield work, inspect the repo first. Ask the user to decide only after citing the file, symbol, or pattern that created the choice.

## A low ambiguity score is not execution approval

Deep Interview ends at a spec plus approval options. Even a clear spec must not trigger ralplan, ultragoal, team, commits, formatters, or product source edits from the interview runtime.

## Auto-mode output is advisory until validated

Greenfield research candidates and opted-out answers must pass exact-shape validation. Invalid output increments diagnostics and falls back to manual questioning; it is not silently trusted.

## Session language is part of the contract

If the initial idea or active state indicates Korean, user-facing questions, progress text, options, and spec prose remain Korean. Code identifiers, file paths, commands, and quoted source stay unchanged.

## Ontology drift means feature questions are premature

When the core nouns keep changing, ask what the core thing is before asking about fields, UI, or implementation. Otherwise scoring will look better than the actual shared understanding.
